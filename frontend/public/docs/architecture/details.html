AI SOC Assistant · Query Flow Explainer

How a SOC question travels through the governed assistant

Implementation-accurate walkthrough of the live /chat pipeline under the Resource Planner graph spine: Query Understanding, 105 taxonomy, use-case catalog, five route skills (including guided investigation rescue), parallel specialist fan-out, the Stage 4B evidence-collection loop, safety gates, Knowledge-page detection coverage, and analyst answer cards. Updated 2026-07-24 after the north-star cutover.

Core principle

The assistant is not a free-form autonomous agent. Deterministic policy controls routing, SPL validation, MCP execution, MITRE status, severity, and final answer safety.

LLM advisory SPL review-only MCP gated MITRE governed RP graph default RunContract canonical Dispatch V2 (flag-off) 4B evidence loop HIL protected

Meeting script read first

The 60-second walkthrough for a leadership or customer demo. Say this top-to-bottom; every claim below is backed by a section in this guide.

1

“Start with the user query. The live hop sequence is: user query → bootstrap/query understanding → route setup → parallel specialist fan-out (Skill, Knowledge, MCP, SPL) → fan-in merge into one validated work bundle → dispatch to RAG-only, composed-plan, or SPL path → optional SPL source resolution → governance chain → final analyst response (1, 2, 2a). This is a governed agentic flow: specialists and LLM sidecars can propose routes, plans, evidence needs, SPL candidates, and narration, while policy gates approve sensitive outcomes such as SPL execution, MCP access, MITRE status, and severity. Response notes show Orchestration: resource_planner_hierarchy.”

2

“Query Understanding checks the 105 taxonomy and the use-case catalog (4). A match uses a governed route. An out-of-registry but hunt-shaped question takes the fifth skill, guided_investigation — not weak knowledge recall (5, 6). Unsafe containment requests are blocked to human review and never enter guided mode.”

3

“One canonical RunContract is the single source of truth for the turn — preview, HIL, source-evidence counts, and route authority all read from it, so the trace can’t contradict the answer (2b, 2c).”

4

“When MCP is allowed, the Stage 4B evidence loop runs bounded, read-only discovery hops before adjudication and again after any gated execution (4B). Guided hunts use guided_hybrid_dispatch when the hybrid flag is on: InvestigationPlan → Validator A → ResourcePlan → Validator B → safe planned/collected evidence → RAG. Execution is OFF by default and fails closed without credentials.”

5

“Every LLM hop is a governed sidecar — failover chain, per-turn budget, grounding guards, and a fail-closed validator. Any failure falls back to the governed non-LLM answer path, so the analyst still gets a safe response (8c).”

6

“Finalize merges discovery into source_evidence, runs the sidecar lane, and produces an analyst response card — not raw LLM prose (12). The Knowledge page shows MITRE detection gaps read-only (14).”

One-line close: “The LLM and specialists make it adaptive; governance makes it safe. Severity, MITRE, SPL execution, and MCP never leave controlled approval gates.”

1. The complete traversal updated

Seven reader-level stages on every live /chat request. Internal route, intent, adjudication, and evidence-planning workers are shown as one contract-building stage because they prepare the same handoff for Resource Planner fan-out.

1

User Query

Analyst asks a SOC question in natural language. Session context may refine follow-ups.

2

Known Question + Catalog Check

Produces exactly one match path M1–M5 (“did we recognize it?”). M1–M4 continue through known-path detail completion; M5 hunt-shaped questions route directly to S5 guided investigation.

3

Known-Path Details or S5 Guided

M1–M4 run a parallel detail-completion node that verifies required catalogue/source/profile details and fills blanks before ResourcePlan handoff. M5 goes straight to S5, where guided investigation builds an InvestigationPlan / ResourcePlan under review-only guardrails.

4

Parallel Specialist Fan-Out

Resource Planner receives either the completed M1–M4 contract or the S5 guided handoff, then fans out to Skill, Knowledge, MCP, and SPL specialists in parallel.

5

Fan-In Merge

Specialist reports merge into one validated work bundle and resource plan. Blocked, unavailable, or off-policy resources are recorded instead of silently used.

6

Dispatch + Collection

Dispatch goes to one path: RAG-only, composed plan, or SPL workflow. SPL paths create candidate SPL, may run pre-MCP RAG, resolve source placeholders, and enter the MCP gate only when eligible.

7

Governance + Final Answer

Runs SPL validation, MCP execution gate, context sufficiency, facts/severity/MITRE handling, answer guard, HIL/policy veto, final composition, validation, trace, and analyst card.

Governed LLM sidecars may appear during intent, planning, SPL candidate work, guided investigation, evidence observation, and final narration. Exact-105 / T0 matches often skip early LLM advisors; catalogue-only or uncertain matches may use them as non-authoritative help. They propose; approval gates decide sensitive outcomes. 2a. Resource Planner hierarchy — production spine cutover

North-star cutover (plans/2026-07-23_1315_resource-planner-north-star-cutover.md, Done). One production orchestration spine; specialists propose; code workers execute; governance vetoes unsafe actions. Narrative companion: docs/architecture/ideal_langgraph_resource_planner.md.

RP graph default

routes_chat / routes_chat_stream call run_chat_via_resource_planner_graph when LANGGRAPH_ORCHESTRATION_ENABLED=true. Analyst-visible note: Orchestration: resource_planner_hierarchy. (no “parity mode”).

Parallel specialists

LangGraph Send fan-out: Skill · Knowledge · MCP · SPL. Merge sorts reports, runs apply_specialist_reports(), then writes validated_work_bundle only after validate_bundle_policy_parity().

Catalogue live bind

match_catalogue_tier() + live_router_bind.py fill blanks in graph_node_query_to_intent (e.g. typo lgon → auth_failed_login_spike). COE/manual slots and non-SOC guards still win.

Topology (v1 Option A): bootstrap → route_setup → Resource Planner delegate → parallel specialists → RP merge → dispatch (prepare_rag_only / composed_dispatch / workflow_spl) → source-resolve when needed → governance (spl_validate → mcp_execution_gate → context_sufficiency → decide_facts → answer_guard → human_review → policy_veto → finalize → validate_final_answer). Specialists enrich owned args_template fields only; they do not revise route, intent, or evidence-plan authority. LLM-primary specialist planning is deferred.

Fail-loud policy (B2)

Unhandled RP defects on /chat return a sanitized HTTP 500 with chat_pipeline_failed telemetry. Stream emits reporter.failed. There is no silent catch-and-fallback to a second full runner. response=None uses the degraded facade (build_rp_degraded_placeholder_response), not a recursive pipeline.

Rollback + retirement

Operational rollback: LANGGRAPH_ORCHESTRATION_ENABLED=false + process restart → temporary build_live_chat_response path. Linear LangGraph removed from api/graph from /chat entrypoints; legacy harness only). Debug traces list RP decision_log nodes (resource_planner.delegate → specialist.* → resource_planner.merge) on live turns.

Dry-run matrix (ask_chat, 2026-07-24): typo failed-login → spl_generation / auth_failed_login_spike (candidate only, HIL); ransomware playbook → knowledge_recall (no SPL); OT overnight hunt → guided_investigation (no MCP exec); MITRE without alert → intent_clarification. 2b. Canonical RunContract — one source of truth new

Every live /chat turn (control plane on or off) now builds a single RunContract / RouteContract in graph state. It ends the “competing truths” class of bug: the analyst card, the audit trace, HIL, and evidence counts all read from the same contract instead of re-deriving state in each surface.

Single HIL truth

action_capability.hil = governance_trace.effective_hil = run_contract.effective_hil. One human-in-the-loop verdict, projected everywhere — never two disagreeing gates.

Honest evidence counts

collected_evidence_count comes only from telemetry that was actually collected. Collected / review-only / candidate artifacts are kept in separate buckets so the card can’t imply data it never fetched.

One route authority

Shadow comparisons (route_authority_compare, routing_skill_resolution) re-project onto canonical_run_contract; the raw shadow lives under raw_shadow_compare for audit only.

Planned vs collected discovery

Execution off (default posture)

MCP_GLOBAL_EXECUTION_ENABLED=false (or mock/live per-server off). Discovery hops record outcome=planned, collection_status=planned, warning discovery_hop_planned_only. Analyst runs the checklist manually.

Execution on (mock or live)

Global + server execution flags on. execute_loop_discovery_hop calls the connector; rows pass evidence_sanitizer; collection_status=collected. Facts flow into structured_context; narration still uses fact statements only (no raw row dump).

Loop eligibility: skipped when mcp_allowed=false or the turn is RAG-only (policy / knowledge paths). Composed Resource Planner dispatch does not disable the loop — discovery may still run before composed steps when MCP is allowed.

6. The five live route skills

Route skills are broad work modes, not the full taxonomy of all possible SOC questions.

attack_discovery

Governed investigation path for known attack or detection use cases.

spl_generation

SPL authoring and validation path. Output is review-only unless gated.

knowledge_recall

SOP, playbook, explain, policy, and RAG-based answers.

alert_summary

Summarizes existing alert evidence and highlights analyst next steps.

guided_investigation

Deterministic rescue for out_of_registry + hunt-shaped questions. With the hybrid flag off: legacy review-only RAG guidance. With AI_SOC_GUIDED_HYBRID_INVESTIGATION_ENABLED: guided_hybrid_dispatch (baseline InvestigationPlan → optional bounded LLM proposal → Validator A → validated ResourcePlan → Validator B → guided collection → RAG). No free-form SPL, action tools, or remediation.

Key rule: low confidence is not a skill. guided_investigation is a skill. Low confidence remains metadata.

7. Internal cybersecurity skills library

The internal skills library is active mainly inside Resource Planner, but it touches multiple nodes. Assume these skills are already built into the product as governed internal capabilities.

Simple explanation: Route Skill decides the broad mode. Resource Planner then chooses which internal skills should shape the answer, which resources should be used, and which actions must be skipped or reviewed.

out_of_scope No / policy path Query Understanding → Route/Triage → Clarification or blocked path Prevents non-SOC or unsupported requests from receiving fabricated SOC answers.

8. LLM usage updated

The LLM helps understand and narrate. It does not own policy or tool execution.

LLM can help with (advisory only)

  • Route and intent candidate suggestions in shadow / assist modes
  • Clarification question wording
  • Review-only SPL draft suggestions on governed paths
  • Readable narration of deterministic analyst-summary prose
  • Guided hybrid (flag on): bounded InvestigationPlan propose inside guided_hybrid_dispatch — validated by Validator A before Resource Planner mapping

Legacy guided (hybrid flag off) keeps deterministic hypotheses/checklist from guidance_templates.py. Hybrid flag on adds LLM propose as planner input only; Validator B still blocks free-form query and action tools; safe-catalog rows are not surfaced as generic SPL execution eligibility.

LLM cannot do

  • Override exact 105 or catalog authority
  • Approve SPL or execute MCP
  • Call tools directly
  • Claim MITRE without evidence
  • Assign severity without policy
  • Invent indexes, sourcetypes, fields, or live results
  • Bypass human approval

8c. Governed LLM sidecar pipeline new

Every LLM hop on the live /chat path runs as a governed sidecar: it proposes prose or candidates, is validated or dropped, and never holds authority. The chain below is the same for intent advisory, missing-evidence, rationale, and composer narration.

01 · RESOLVE

Failover chain

Qwen (flag-gated) → local Foundation-Sec → Instruct fallback. Deduped by URL. Returns the endpoint that actually answered.

02 · BOUND

Wall-clock timeout

Persistent executor, no blocking join. Socket ceiling = wrapper (120s) so a slow single-slot model is never silently capped. Hung call → abandon → fallback.

03 · BUDGET

Per-turn cap

Session-scoped TurnLlmBudget in graph state: max 2 sidecar + 1 narration. T0 / exact-105 / clarification skip the call entirely.

04 · GUARD

Validate or drop

JSON/schema adapter, cite-only grounding guard (no invented IP / index / hash / SPL), out-of-catalog notice guard, fail-closed final-answer validator.

05 · MERGE / FALL BACK

Deterministic floor

Pass → prose merged (facts untouched). Fail / timeout / unconfigured → deterministic answer (design goal: same analyst-visible facts as LLM-off; traces may still record skip reasons).

Weak-case & out-of-catalog composition

For out-of-catalog / weak / failover questions the composer narrates a body from skills + RAG + governed facts — the on-the-fly advantage over fixed SOAR. Threshold HIL: below AI_SOC_LLM_COMPOSE_HIL_THRESHOLD the body still renders but carries an analyst-review gate; any proposed MCP action always gates.

out-of-catalog notice kept cite-only-retrieved execution_eligible = false severity / MITRE deterministic

Context package & promotion gate

GovernedContextPackage feeds sidecars redacted RAG, skill metadata, and MCP tool hints (descriptions only — never schema or credentials), truncated to the role budget. Row text and prompt blocks pass through evidence_sanitizer (A1). The build_llm_role_scorecard reads control_plane_trace and gates promotion: a role is trusted only at verdict HEALTHY (fallback < 10%, agreement ≥ 70%, n ≥ 20).

HEALTHY DEGRADED INSUFFICIENT_DATA
Authority boundary: the sidecar lane can rewrite prose and propose candidates only. It never sets severity, MITRE status, SPL approval, or execution_eligible, never selects or runs an MCP tool, and never reaches the Experience Center fixture path. On failure the answer falls back to the deterministic floor (see Step 3 contract + governance chain — sidecars do not perform resource decomposition).
