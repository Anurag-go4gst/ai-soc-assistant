# Intent→MCP tool routing hardening

## Objective

Make MCP tool selection explicit and auditable per analyst intent, on the **existing** spine (evidence-loop HUB + `mcp_tool_playbook.json` + `mcp_execution_gate`), replacing the external "Node 5B/7C/7D" blueprint with repo-true structures. Done means: playbook declares per-tool intent hints the deterministic planner enforces; metadata data-silence becomes an advisory HIL routing signal (never a silent hard halt); `splunk_run_saved_search` gains a name allowlist (deny-all default); `splunk_get_kv_store_collections` is onboarded surface-pending; `splunk_get_user_list` stays blocked with the insider-threat alternative documented; a corrected routing doc with the three example chronologies exists for dev handoff.

**Phase 2 (items 8–13) — governed evidence observation.** Today no LLM ever reads MCP row content (`GovernedSynthesisPackage` carries aggregates/refs only), so questions like "what did the last 50 rows show" cannot be answered beyond counts. Phase 2 adds an `evidence_observer` sidecar role: after a gated `run_query` (or discovery hop) returns bounded sanitized rows, the small model (design floor: ≤2B-class, one-shot worked example, strict JSON grounded-claim schema) emits advisory observations that cite row indexes; a deterministic grounding check verifies every cited token actually appears in the cited rows before the observation may surface. Governed ReAct: LLM = Reason only (observe rows, optionally propose next hop); deterministic HUB = Act (validates proposal against playbook intents + `MAX_MCP_HOPS`, executes; execution tools keep HIL). Severity/MITRE/`execution_eligible` stay deterministic authority; LLM observations are provenance-tagged `llm_observation` and never auto-feed those decisions. Full per-call telemetry on the existing trace spine (`control_plane_trace` + `ai_trace_runs`), no side door, EC path untouched, no new flags (reuses live-synthesis gates + role registry).

**Phase 3 (items 16–20) — canonical reference-knowledge path.** Live audit (2026-07-05) showed ATLAS taxonomy questions fail in `/chat` two ways: `knowledge_recall` + MITRE-without-alert hygiene demands alert context (rule built for alert *mapping*, blind to *taxonomy* asks), or detection-ask SPL floors capture "list techniques relevant to…" and draft SPL against nonexistent indexed ATLAS data. Root cause is architectural: CVE, enterprise ATT&CK, ATLAS, SOC-KB were each wired ad hoc (CVE read model + `cve_adapter`; ATT&CK alert-mapping + `mitre_finalize`; ATLAS resolver reachable only from the Knowledge API and T2 advisory grounding — "never routes" by original scope). Phase 3 replaces per-dataset wiring with **one** canonical path: reference-dataset registry (ID patterns + keyword domains + resolver binding) → deterministic `reference_taxonomy` answer shape → `knowledge_recall`/`reference_knowledge` request mode → generalized `reference_finalize` stage resolving IDs offline into `StructuredContext` facts with citations → governed narration. Method is probe-question-driven: ten fixed probes — six positive (two failing ATLAS asks, ATT&CK lookup, CVE lookup, alert-mapping non-regression, SPL non-regression) plus four **negative probes** that must NOT match the taxonomy shape (CVE exploitation hunt, live T-ID activity ask, alert mapping, coverage-dashboard meta-ops) — are the acceptance contract; every routing change is traced against all ten. Deterministic signals will miss phrasings: a **candidate-constrained LLM shape advisor** at the initial node suggests a shape from the closed list (or "none"), is ALWAYS recorded in the trace even when unused (mismatch traces are the mining source for expanding deterministic signals later), and may promote only under deterministic guard — never override a deterministic match. **Answer-quality evals** assert contracts on the final answer: resolved IDs with names, zero hallucinated IDs (every ID in the answer must exist in resolver output), citations present, no clarification demand on taxonomy asks, honest-gap statements. Onboarding a future dataset (CWE, D3FEND, OWASP LLM Top-10, …) = one registry entry + resolver, **zero** new routes/floors/flags — proven by a contract test using a synthetic dataset.

## Governance invariants (unchanged, this plan must not touch)

- Read-only discovery auto-executes; `splunk_run_query` / `splunk_run_saved_search` always one-click HIL (danger-tier plan 2026-07-04_1610).
- `splunk_get_user_list` stays hard-blocked (`admin_or_sensitive_tool`); SAIA tools stay blocked.
- LLM never calls MCP. Phase 2 refines but does not weaken this: the LLM may *observe* sanitized bounded rows and *propose* a next hop; every act (tool selection, execution, termination) stays deterministic HUB authority (`evidence_loop.py`), bounded by `MAX_MCP_HOPS`. No free ReAct.
- Severity, MITRE status, `execution_eligible`, allowed actions stay deterministic; `llm_observation` output is advisory, provenance-tagged, and gated by a deterministic grounding check before display.
- Row content sent to the LLM is attacker-influencable (log fields) — always passes the prompt-injection filter first; LLM output is treated as untrusted (schema adapter + grounding check), never as instructions.
- Free-form SPL prohibited; validator allowlists (`SPL_ALLOWED_INDEXES`) unchanged.
- Post-execution empty-result flow (broaden-eligible / honest negative, `evidence_loop.py` ROUTE_BROADEN) unchanged.
- No new feature flags: Phase 2 is gated by the existing `ai_soc_llm_final_synthesis_enabled` + `ai_soc_llm_live_synthesis_enabled` pair plus role availability in the LLM role registry. EC/demo path never invokes the observer.
- All observer calls respect `turn_llm_budget` wall-clock deadlines; budget exhaustion degrades to deterministic-facts-only answer, never an error.

## LLM intensity policy (measured live on this VPS, 2026-07-05)

Probes against the running Foundation-Sec-8B (`:8081`, idle box, steal 0):

| Role shape | Measured | Policy |
|---|---|---|
| Constrained-output classification (≤10 tok out, static system prompt): shape advisor | Zero-shot bare list: **4/8**, heavy `alert_mapping` bias — including a miss on the live-failing ATLAS query. Few-shot (definitions + 6 examples): **8/8**, 1.0–2.4s warm (9.7s cold prefill, then server KV-cache holds the static prefix) | **Main-path advisory on every routed turn** — not shadow-only. Few-shot prompt contract is mandatory (zero-shot is measurably unsafe). 10s bound, no failover. Deterministic authority + guarded promotion unchanged. |
| Long-output structured (observer, ~90 tok out) | One-shot prompt → perfect grounded JSON, correct `row_refs`, no fences, first try; **24.6s** idle (~3.7 tok/s decode; worse under documented steal bursts) | Advisory on main path but **1 call/turn cap + budget guard stays** on this VPS. Lift cap only at COE-class serving (5000 tok/s → sub-second). |
| Long-output prose (narration, rationale) | (prior measurements: 30–120s/call) | Unchanged: budget-capped, fallback to deterministic draft. |

Rule of thumb this encodes: **output length, not model size, is the VPS cost driver** — the KV-cached static prefix makes short-output roles nearly free, so they get promoted; long-output roles wait for COE serving.
