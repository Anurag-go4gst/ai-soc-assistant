# Splunk Context Document — Template (COE-Reviewed Static Grounding)

> **Purpose.** This document is the *static, human-approved* grounding context the AI-SOC
> uses for SPL generation, SPL validation, MCP tool selection, and evidence packaging
> for the **PGCIL OT-SOC** engagement. It is a control artifact, not runtime configuration.
>
> **Lifecycle (must be respected).**
> 1. **Generate once** using safe, read-only Splunk metadata tools (`get_splunk_metadata`,
>    `list_tools`, `splunk_get_indexes`). No live ad-hoc inspection at runtime.
> 2. **Human review** by the COE. Every allow/exclude decision is signed off.
> 3. **Ship as static approved context.** Versioned, frozen, checked in.
> 4. **Runtime never freely inspects the live Splunk environment.** It reads this document.
>    Refreshing it is a deliberate, reviewed action — never an automatic background scan.
>
> **Inclusion AND exclusion lists are both authoritative.** A field/index/sourcetype/object
> that is not on an allowlist is denied by default; an explicit exclusion list additionally
> records *why* a tempting target is forbidden, so reviewers do not re-litigate it.
>
> **How to use this template.** Fill every `<PLACEHOLDER: …>` and `TBD`. Empty table rows are
> examples to be replaced. Do not delete the "How to fill" note in each section until the COE
> has signed that section. Sections marked **Stage 4 future** / **Stage 5 future** stay skeletal
> until the engagement formally enters that stage.

## 16. Mapping to Evidence Package Masking Rules

> Maps context-doc fields to evidence minimisation/masking. **Current state: these are
> binding points, not yet fully enforced.** `data_minimizer.minimize_context`
> (`backend/app/safeguards/data_minimizer.py`) only strips keys containing `token`/`password`.
> `validate_evidence` (`backend/app/safeguards/evidence_validator.py`) is a shape-only stub.
> §7's sensitive-field list is the authoritative spec those functions must grow to honor.

| Context doc section | Evidence/masking binding point | Current behavior | Required behavior |
|---|---|---|---|
| §7 Sensitive fields (drop) | `data_minimizer.minimize_context` | strips `token`/`password` keys | drop all §7 "drop" fields |
| §7 Sensitive fields (mask/hash/truncate) | (future masking layer) | none | apply per-field rule before evidence/LLM |
| §6 Field allowlist | evidence column filter | none | only allowlisted output fields in evidence |
| §13 Result preview cap | `mcp_execution_gate.RESULT_PREVIEW_CAP=5` | enforced | keep; evidence preview ≤ cap |
| Data boundary | `docs/data-boundary.md` | documented | raw logs/secrets never to LLM |

- Evidence rule of thumb: an evidence package may contain only (a) §6-allowlisted fields,
  (b) with §7 masking applied, (c) capped to §13 limits. Anything else is a leak.
