AI SOC Assistant · Query Flow Explainer

How a SOC question travels through the governed assistant

Implementation-accurate walkthrough of the live /chat pipeline: Query Understanding, 105 taxonomy, use-case catalog, five route skills (including guided investigation rescue), resource planning, the Stage 4B evidence-collection loop, safety gates, Knowledge-page detection coverage, and analyst answer cards.

Core principle

The assistant is not a free-form autonomous agent. Deterministic policy controls routing, SPL validation, MCP execution, MITRE status, severity, and final answer safety.

LLM advisory SPL review-only MCP gated MITRE governed RunContract canonical Dispatch V2 (flag-off) 4B evidence loop HIL protected

Meeting script read first

The 60-second walkthrough for a leadership or customer demo. Say this top-to-bottom; every claim below is backed by a section in this guide.

1

“Every SOC question travels the same governed pipeline — ten pipeline.py nodes (§1, §2). It is not a free-form agent: deterministic policy owns routing, SPL approval, MCP execution, MITRE status, and severity. The LLM only advises and narrates.”

2

“Query Understanding checks the 105 taxonomy and the use-case catalog (§4). A match uses a governed route. An out-of-registry but hunt-shaped question takes the fifth skill, guided_investigation — not weak knowledge recall (§5, §6). Unsafe containment requests are blocked to human review and never enter guided mode.”

3

“One canonical RunContract is the single source of truth for the turn — preview, HIL, source-evidence counts, and route authority all read from it, so the trace can’t contradict the answer (§2b, §2c).”

4

“When MCP is allowed, the Stage 4B evidence loop runs bounded, read-only discovery hops before adjudication and again after any gated execution (§4B). Execution is OFF by default and fails closed without credentials.”

5

“Every LLM hop is a governed sidecar — failover chain, per-turn budget, grounding guards, and a fail-closed validator. Any failure falls back to a deterministic answer that is byte-identical to running with the LLM off (§8c).”

6

“Finalize merges discovery into source_evidence, runs the sidecar lane, and produces an analyst response card — not raw LLM prose (§12). The Knowledge page shows MITRE detection gaps read-only (§14).”

One-line close: “The LLM makes it fluent and fast; deterministic policy makes it safe. Severity, MITRE, SPL execution, and MCP never leave governed control.”

1. The complete traversal updated

Eight pipeline stages on every live /chat request. Section 2 shows the same sequence with route and execute branches.

1

User Query

Analyst asks a SOC question in natural language. Session context may refine follow-ups.

2

Query Understanding

Matches 105 / catalog, extracts entities, and sets signals such as soc_investigation_shaped.

3

Route Skill

Deterministic route from five live skills. OOD hunt rescue sets guided_investigation and rescue_mode.

4

Intent

Exact goal: SOP, SPL, investigation, summary, guided hunt, clarification, or unsafe block. Catalog use-case matches now route to their skill instead of collapsing to clarification. A T0-skipped intent advisor sidecar may run — advisory only.

5

Evidence + Plan

Evidence plan (CP on) and planning path. When mcp_allowed, the 4B HUB may run bounded discovery hops before adjudication. CP off still returns resource_plan_summary for guided hunts.

6

Route Adjudication

CP on: deterministic policy confirms or overrides LLM route hints. Guided rescue is preserved explicitly.

7

Execute Branch

Guided / RAG-only: SOC-KB lookup. Known paths: SPL validation and gated MCP read. Discovery hops are planned when MCP execution is off; collected when global + mock/live gates are on. splunk_run_query stays gated.

8

Finalize

Merge mcp_evidence into source_evidence → AnswerContract → governed sidecars → composer narration (grounding + notice guards) → fail-closed validator → control_plane_trace + analyst card. See §8c and §4B.

Steps 4 and 8 each open a governed LLM sidecar lane — non-authoritative hops that propose prose/candidates, are validated or dropped, and never change severity, MITRE status, SPL approval, or MCP execution. Jump to the sidecar pipeline →

2b. Canonical RunContract — one source of truth new

Every live /chat turn (control plane on or off) now builds a single RunContract / RouteContract in graph state. It ends the “competing truths” class of bug: the analyst card, the audit trace, HIL, and evidence counts all read from the same contract instead of re-deriving state in each surface.

Single HIL truth

action_capability.hil = governance_trace.effective_hil = run_contract.effective_hil. One human-in-the-loop verdict, projected everywhere — never two disagreeing gates.

Honest evidence counts

collected_evidence_count comes only from telemetry that was actually collected. Collected / review-only / candidate artifacts are kept in separate buckets so the card can’t imply data it never fetched.

One route authority

Shadow comparisons (route_authority_compare, routing_skill_resolution) re-project onto canonical_run_contract; the raw shadow lives under raw_shadow_compare for audit only.

Planned vs collected discovery

Execution off (default posture)

MCP_GLOBAL_EXECUTION_ENABLED=false (or mock/live per-server off). Discovery hops record outcome=planned, collection_status=planned, warning discovery_hop_planned_only. Analyst runs the checklist manually.

Execution on (mock or live)

Global + server execution flags on. execute_loop_discovery_hop calls the connector; rows pass evidence_sanitizer; collection_status=collected. Facts flow into structured_context; narration still uses fact statements only (no raw row dump).

Loop eligibility: skipped when mcp_allowed=false or the turn is RAG-only (policy / knowledge paths). Composed Resource Planner dispatch does not disable the loop — discovery may still run before composed steps when MCP is allowed.

6. The five live route skills

Route skills are broad work modes, not the full taxonomy of all possible SOC questions.

attack_discovery

Governed investigation path for known attack or detection use cases.

spl_generation

SPL authoring and validation path. Output is review-only unless gated.

knowledge_recall

SOP, playbook, explain, policy, and RAG-based answers.

alert_summary

Summarizes existing alert evidence and highlights analyst next steps.

guided_investigation

Deterministic rescue for out_of_registry + hunt-shaped questions. With the hybrid flag off: legacy review-only RAG guidance. With AI_SOC_GUIDED_HYBRID_INVESTIGATION_ENABLED: hybrid orchestrator (InvestigationPlan → validated ResourcePlan → planned discovery / safe-catalog hops). No MCP execution or free-form SPL.

Key rule: low confidence is not a skill. guided_investigation is a skill. Low confidence remains metadata.

7. Internal cybersecurity skills library

The internal skills library is active mainly inside Resource Planner, but it touches multiple nodes. Assume these skills are already built into the product as governed internal capabilities.

Simple explanation: Route Skill decides the broad mode. Resource Planner then chooses which internal skills should shape the answer, which resources should be used, and which actions must be skipped or reviewed.

Where the skills library touches the flow

Examples of how skills improve answers

Example 1: Failed-login spike

Question: “Investigate failed login spike on APP-01.”

Skills used: attack_discovery, spl_generation, spl_validation, evidence_collection, context_sufficiency, answer_guard.

Improvement: The answer includes SPL, failed-login volume checks, success-after-failure correlation, affected users, MITRE Candidate caution, severity policy, and analyst next steps.

Example 2: OT chatter

Question: “Strange OT chatter to a brand new external host overnight, anything to hunt?”

Skills used: guided_investigation, evidence_collection, context_sufficiency, synthesis, answer_guard.

Improvement: Instead of low-confidence knowledge recall, the answer gives hunt hypotheses, data sources, baseline checks, vendor/CDN validation, and clear limitations.

Example 3: Brute-force SOP

Question: “Show me the brute-force login SOP.”

Skills used: knowledge_recall, context_sufficiency, synthesis, answer_guard.

Improvement: The answer stays RAG-only and gives procedure, escalation criteria, and policy citations instead of wrongly generating SPL.

Important: Skills shape the plan and the answer. They do not execute tools by themselves. MCP, SPL execution, MITRE status, severity, and actions remain under deterministic gates.

8. LLM usage updated

The LLM helps understand and narrate. It does not own policy or tool execution.

LLM can help with (advisory only)

  • Route and intent candidate suggestions in shadow / assist modes
  • Clarification question wording
  • Review-only SPL draft suggestions on governed paths
  • Readable narration of deterministic analyst-summary prose
  • Guided hybrid (flag on): bounded InvestigationPlan propose inside guided_hybrid_dispatch — validated by Validator A before Resource Planner mapping

Legacy guided (hybrid flag off) keeps deterministic hypotheses/checklist from guidance_templates.py. Hybrid flag on adds LLM propose as planner input only; Validator B still blocks free-form query and action tools; safe-catalog rows are not surfaced as generic SPL execution eligibility.

LLM cannot do

  • Override exact 105 or catalog authority
  • Approve SPL or execute MCP
  • Call tools directly
  • Claim MITRE without evidence
  • Assign severity without policy
  • Invent indexes, sourcetypes, fields, or live results
  • Bypass human approval

8c. Governed LLM sidecar pipeline new

Every LLM hop on the live /chat path runs as a governed sidecar: it proposes prose or candidates, is validated or dropped, and never holds authority. The chain below is the same for intent advisory, missing-evidence, rationale, and composer narration.

01 · RESOLVE

Failover chain

Qwen (flag-gated) → local Foundation-Sec → Instruct fallback. Deduped by URL. Returns the endpoint that actually answered.

02 · BOUND

Wall-clock timeout

Persistent executor, no blocking join. Socket ceiling = wrapper (120s) so a slow single-slot model is never silently capped. Hung call → abandon → fallback.

03 · BUDGET

Per-turn cap

Session-scoped TurnLlmBudget in graph state: max 2 sidecar + 1 narration. T0 / exact-105 / clarification skip the call entirely.

04 · GUARD

Validate or drop

JSON/schema adapter, cite-only grounding guard (no invented IP / index / hash / SPL), out-of-catalog notice guard, fail-closed final-answer validator.

05 · MERGE / FALL BACK

Deterministic floor

Pass → prose merged (facts untouched). Fail / timeout / unconfigured → deterministic answer, byte-equivalent to LLM-off.

Weak-case & out-of-catalog composition

For out-of-catalog / weak / failover questions the composer narrates a body from skills + RAG + governed facts — the on-the-fly advantage over fixed SOAR. Threshold HIL: below AI_SOC_LLM_COMPOSE_HIL_THRESHOLD the body still renders but carries an analyst-review gate; any proposed MCP action always gates.

out-of-catalog notice kept cite-only-retrieved execution_eligible = false severity / MITRE deterministic

Context package & promotion gate

GovernedContextPackage feeds sidecars redacted RAG, skill metadata, and MCP tool hints (descriptions only — never schema or credentials), truncated to the role budget. Row text and prompt blocks pass through evidence_sanitizer (A1). The build_llm_role_scorecard reads control_plane_trace and gates promotion: a role is trusted only at verdict HEALTHY (fallback < 10%, agreement ≥ 70%, n ≥ 20).

HEALTHY DEGRADED INSUFFICIENT_DATA
Authority boundary: the sidecar lane can rewrite prose and propose candidates only. It never sets severity, MITRE status, SPL approval, or execution_eligible, never selects or runs an MCP tool, and never reaches the Experience Center fixture path. On any failure the answer is exactly what it would be with the LLM disabled.
