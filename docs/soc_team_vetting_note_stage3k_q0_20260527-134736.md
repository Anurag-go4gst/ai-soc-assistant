# Stage 3K-Q0 SOC Vetting Note

Created: 2026-05-27 13:47:36 UTC
Source: `docs/soc_question_taxonomy_stage3k_q0.md`
Scope: SOC/Splunk team review and planning only. No runtime code, SPL templates, SPL validator changes, LLM synthesis, Answer Guard execution, MCP/SPL gate changes, or Experience Center behavior changes are included.

## Purpose

We reviewed 105 SOC analyst questions and grouped them into reusable implementation patterns. The goal is not to build one SPL search or one template per question. The practical implementation model should be pattern-based: one governed capability can answer multiple similar questions when the required data sources, parameters, time windows, lookups, and detection logic are available.

This note asks the SOC/Splunk team to validate three things before implementation planning continues:

- Which questions are highest priority.
- Which Splunk data sources and enrichments are available.
- Which behavioral detections already exist as vetted correlation searches or detection content.

## Executive Summary

- 105 SOC analyst questions reviewed.
- 20 reusable internal patterns identified.
- 20 representative questions proposed for first coverage planning.
- The actual live demo may show fewer than 20 questions, but the coverage plan should span these 20 representative questions.
- CIM/tstats implementation still requires Stage 3K-Q1 SPL validator and template-schema safety work before any CIM-first template is created.

The current SPL validator is raw-search shaped. The taxonomy can identify the ideal source class, but it does not make CIM/tstats implementation ready.
